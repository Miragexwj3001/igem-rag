# iGEM RAG 生成质量评估报告 (Phase 3)

**日期**：2026-04-26  
**评估题数**：50 题（规则化 25 + LLM生成 25）  
**评估范围**：完整 RAG 流程（检索 + 生成），生成回答的质量  
**评审模型**：qwen-plus (LLM-as-Judge)  

---

## 实验步骤

### 1. 题目采样

从 `eval/eval_dataset.json`（387 题）中随机抽取 50 题（seed=42）：
- 规则化题 25 道（问题含具体团队名+年份）
- LLM 生成题 25 道（问题不含团队名/年份，语义泛化）

### 2. RAG 流程

对每道题完整运行 `QwenRAGSystemOptimized`：

```
检索：hybrid_retrieve(k=8)
         ↓
生成：generate_prompt() → call_qwen_api() (qwen3.5-plus, max_tokens=3000)
         ↓
输出：answer + retrieved_sources
```

### 3. 质量评估（LLM-as-Judge）

将问题、检索上下文（截取 3000 字）、生成回答送入 `qwen-plus`，评两个维度：

| 维度 | 含义 | 评分 |
|---|---|---|
| **Faithfulness（忠实度）** | 回答的每项陈述是否都有检索上下文支撑 | 1–5 |
| **Relevance（相关性）** | 回答是否切题、有效解答了问题 | 1–5 |

### 4. 引用准确率（程序化）

从回答中提取引用，核验是否存在于检索结果的 metadata 中。

系统实际使用多种引用格式，采用宽松正则覆盖以下格式：
- `[来源：TeamName YYYY]` / `[TeamName YYYY]`
- `**TeamName YYYY**：` / `**【TeamName YYYY】**`
- `(TeamName YYYY)` / 正文嵌入 `TeamName YYYY年`

> **局限性**：评估脚本仅保存了答案前 400 字（`answer_preview`），答案中段的综合分析部分无法检测。因此：
> - 每题平均 1.5 处引用被检测到（远少于实际引用数）
> - 答案开头通常首先引用问题直接相关的来源，导致检测到的准确率偏高
> - **核心质量指标应以 LLM-as-Judge 的 Faithfulness 评分为准**（Judge 读取完整答案）

## 低分样例分析

### Faithfulness = 2（唯一案例）

**类型**：LLM 生成题  
**问题**：这项工作如何通过多维度的社会调研和公众互动，验证其技术方案在真实医疗场景中的实际需求和接受度？

**根本原因**：问题跨越多支队伍做综合分析，LLM 在回答中引用了未出现于检索结果的来源（Peking 2015、BNDS_CHINA），并将 Cornell/Freiburg 的内容重复引用为不同来源。  
→ 典型的**跨队伍合成回答引发的幻觉**。

---

### Faithfulness = 3（4 个案例）

| 问题类型 | 问题摘要 | 缺陷描述 |
|---|---|---|
| LLM 生成 | 公众拓展活动是否围绕同一科学目标 | 提及 IIT-Bombay 2024 / NTNU_Trondheim 2018 无上下文依据 |
| LLM 生成 | TEV 蛋白酶切割激活荧光信号机制 | 提及 Slovenia 2016 及 FRET 原理（标为"通用知识"但原文未提） |
| LLM 生成 | 工程菌在肠道中定植并分泌 IL-10 | 提及 TU-Eindhoven 2023 但上下文无此来源 |
| 规则化 | ETH_Zurich 2017 湿实验困难 | 生物安全/伦理细节无直接依据，属推断延伸 |

**共同模式**：LLM 用自身知识补充上下文未提供的细节，或跨队伍综合时混入未检索到的团队信息。

## 发现与分析

### 1. 相关性几乎满分（4.98/5）

系统在理解问题、给出切题回答上表现优秀，49/50 道题得到满分。规则化题更是 25/25 全部满分，说明对精确定向查询的回答能力非常稳定。

### 2. 忠实度总体良好，LLM 生成题是主要风险点

规则化题忠实度极高（4.84/5，23/25 满分），主要因为问题含团队名+年份，检索精准，LLM 可以直接引用。

LLM 生成题忠实度下降（4.20/5），根本原因是：
- 问题不含具体来源限制，LLM 倾向于**跨队伍综合回答**
- 综合回答时容易引入未被检索到的背景知识或相似来源

### 3. 引用幻觉模式与 Phase 2 一致

所有忠实度低分案例均涉及**引用了上下文中不存在的团队/来源**，与 Phase 2 幻觉测试发现的"队名语义映射"问题高度吻合——LLM 会用相似但不同的队伍信息填充答案。

### 4. Citation Accuracy 的局限性

改进正则后（覆盖多种引用格式），无引用检测从 30/50 降至 **3/50**，共检测到 74 处引用，在答案前 400 字内有效率 100%。然而，由于脚本仅保存了答案前 400 字，答案中段（综合分析、多团队对比部分）的引用无法被检测——而 Faithfulness 低分案例的幻觉引用恰恰出现在这些位置（如 faith=2 的案例在答案后半段引用了未检索到的来源）。**本指标仅作参考，以 Faithfulness 评分为准。**

## 结论

| 指标 | 评分 | 结论 |
|---|---|---|
| Relevance | 4.98/5 | 优秀，系统能准确理解并切题回答 |
| Faithfulness（规则化）| 4.84/5 | 优秀，精确查询场景下回答高度忠实 |
| Faithfulness（LLM生成）| 4.20/5 | 良好，综合分析题有幻觉风险 |

### 优化建议

1. **修复 `generate_prompt()` 约束**（Phase 2 已发现，本次再次验证）：加入队名/年份精确匹配约束，禁止引用上下文中不存在的来源
2. **LLM 生成题的上下文充分性**：对综合型问题，考虑增加 `k`（当前 k=8），召回更多相关来源以减少 LLM 补充自身知识的需要
3. **引用格式标准化**：在 prompt 中指定引用格式为 `[来源：TeamName YYYY]`，便于后续程序化校验
